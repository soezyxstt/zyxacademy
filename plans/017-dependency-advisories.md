## Why this matters

`bun audit` reports high-severity advisories on dependencies that touch security-sensitive reachable code: `better-auth › defu` (prototype pollution, GHSA-737v-mqg7-c878) — auth is a core path; and `firebase-admin › @google-cloud/storage › form-data` (CRLF injection, GHSA-hmw2-7cc7-3qxx) — firebase-admin backs FCM push. Moderate advisories on `inngest › hono` and `qs` are lower priority. Patching the two highs closes the reachable exposure.

- `package.json:37` `better-auth: ^1.6.19`; `package.json:45` `firebase-admin: ^14.0.0`.
- Bun supports `overrides` in `package.json` to force a patched transitive version when a direct bump is not available.

## Steps

### Step 1: Re-audit (after plan 015)

Run `bun audit` and record the current high/critical advisories on reachable runtime deps. Confirm the two headline ones (`defu` via better-auth, `form-data` via firebase-admin) still appear. Ignore dev/build-only advisories.

**Verify**: you have a current list; the two highs are present (or note if already resolved by plan 015).

### Step 2: Resolve `better-auth › defu`

Try, in order, stopping at the first that clears the advisory without breaking typecheck/build:
1. Bump `better-auth` to the latest `^1.x` that pulls a patched `defu` (`bun update better-auth`).
2. If no better-auth release fixes it yet, add an `overrides` entry forcing the patched `defu` version:
   ```json
   "overrides": { "defu": ">=<patched-version>" }
   ```
   (Use the patched version named in the advisory.)

**Verify**: `bun audit` no longer lists the `defu` high; `bun run typecheck` → exit 0.

### Step 3: Resolve `firebase-admin › form-data`

Same approach: bump `firebase-admin`, or add an `overrides` entry for the patched `form-data`. Because firebase-admin backs FCM push, verify the push code path still typechecks (`lib/firebase/admin.ts`, `lib/notifications/**`).

**Verify**: `bun audit` no longer lists the `form-data` high; `bun run typecheck` → exit 0.

### Step 4: Build and smoke the affected paths

Run `bun run build` once. Confirm auth (`lib/auth.ts`) and firebase-admin (`lib/firebase/admin.ts`) still compile and are unchanged in behavior (no API signature changes required).

**Verify**: `bun run build` → exit 0; `bun run lint` → exit 0.

## STOP conditions

- The only version that clears an advisory is a MAJOR bump with breaking API changes (better-auth or firebase-admin) — STOP and report; that is a migration, not a patch, and needs its own plan.
- An `overrides` pin causes install resolution conflicts or a runtime break in `bun run build` — revert the override and report; forcing an incompatible transitive is worse than the advisory.
- The advisory list at Step 1 differs materially from this plan's snapshot — proceed against the CURRENT list and note the difference; do not chase advisories that no longer exist.
