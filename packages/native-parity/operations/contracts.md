# Operations route and contract inventory

Source inspected: `native-migration/operations` commit `e604aecea9d9eae9bcf1d8a7229ea45b608afbd1`. The 49 page files assigned to operations in `plans/native-parallel/routes.tsv` comprise 36 Admin and 13 marketing pages. This is a source inventory, not evidence of native implementation, deployed behavior, complete endpoint enumeration, or passing tests. The callsites below are starting points for tracing operations; inputs, responses, guards, retries, and all nested component calls still require verification against their handlers and tests before implementation. UI and route aliases must not be counted as separate backend operations without an independently different effect or authorization boundary.

All Admin routes inherit `app/(admin)/layout.tsx`: session required, legacy identity ensured, `hasPeran(user.id, "admin")` required, otherwise redirect to `/`. Some page-level guards use `assertTutorOrAdmin`; this does not remove the enclosing Admin layout requirement. An HTTPS handler is a separate public entry point and must enforce its own authorization. For each operation verify the handler guard, validation, bounded response, idempotency and recovery; never rely on a hidden button or a native route guard. Server Actions and direct RSC database or read-model calls are not native HTTPS contracts. A dedicated adapter, if needed, must preserve those server boundaries and results. Do not expose secrets or privileged records in fixtures.

## Validation required before credit

For every actual operation record a stable ID, invoking screen, role, server handler/action/read model, input, authorization, output or effect, retry/idempotency and errors, then link a native caller and focused tests. Distinguish internal, retired, duplicate, web-only and unmapped operations with reasons. Trace nested components, not just page imports. For aliases verify valid, missing and denied parameters, exact redirect destination, encoding, query and Back. Coordinate academic destinations and integration-owned auth, router, shared transport, session, offline and renderer contracts.

For each page verify populated, empty/loading and error/recovery as applicable, long text, locale, theme, accessibility, navigation and permission denial. For three cases per component use matching web references and actual Android and iOS screenshots. Browser screenshots of React Native Web do not prove native parity. Record source commit, device, OS, dimensions, density, font, theme, interaction result, artifacts and differences. Follow `docs/mobile-native.md`, `docs/native-readiness.md`, and the MCP compatibility review in `AGENTS.md`. No visual, device, backend integration or release claim follows from this inventory.
