# Pengelolaan Admin di Expo

`ManagementScreen` menerima path, navigasi, client, akses Admin, dan kunci akun aktif. Integrator mengikat `createManagementClient` ke `NativeSessionTransport`. `ManagementFixtureScreen` dan `createManagementFixture` berjalan tanpa backend. Regresi rute dan status menggunakan 39 kasus deterministik dari `managementCases`. Draft editor tetap tersedia selama area pengelolaan dan sesi yang sama masih terpasang.

## Otorisasi dan hasil operasi

- `GET /api/native/operations/management` memerlukan sesi aktif dan peran Admin. ID akun pada request harus cocok. Preset memakai proyeksi native dari `custom_form_presets`, tabel yang sama dengan `/api/admin/form-presets`. Daftar mengirim ringkasan 20 preset per halaman. Editor mengambil definisi dan revisi melalui detail saat pengguna memilih preset. Editor native memeriksa revisi pada perubahan dan penghapusan. Endpoint PATCH dan DELETE web masih menerima permintaan tanpa revisi. Form, direktori Meet, tautan dan media tetap memanggil endpoint terotorisasi yang ada. Semua request Expo memakai transport yang mengikat origin, akun dan sesi.
- Tautan diskusi Admin dapat membuka thread dan pesan di luar daftar halaman saat ini. Pembacaan memakai jasa diskusi berizin di server dan receipt baca untuk halaman yang benar. Tab laporan membaca antrean moderasi berhalaman dan mengikuti pesan yang dilaporkan. Penanganan atau pengabaian laporan tetap tersedia di web. Pembacaan UI ini mengikuti cakupan diskusi Admin yang sudah ada.
- `POST /api/native/operations/management` memeriksa origin jika dikirim, tipe JSON, akun, dan sesi. Database memeriksa kembali sesi dan hak Admin saat blog, formulir, preset, harga dan tautan ditulis. Mutasi dan receipt idempotensi disimpan secara atomik. Aksi diskusi meneruskan ke pemeriksaan peran dan akses kanal layanan yang sama. Balasan meneruskan ID percobaan yang sama.
- Efek media dan Meet dicatat sebelum handler provider dipanggil. Satu intent yang belum pasti tetap diblokir meskipun perangkat mengirim kunci berbeda. Tentukan hasil di Admin web sebelum aksi lanjutan. Meet delete hanya melaporkan sukses setelah pembacaan provider mengonfirmasi rekaman sudah hilang. Aksi uji memakai implementasi provider sintetis. Preset membaca jadwal lokal lama sebagai waktu Jakarta dan mencegah penerapan pertanyaan lama yang gagal divalidasi.
- Jalur native menggunakan sesi Admin UI. Tidak ada perubahan registrasi alat, OAuth scopes, consent, capability discovery, playbook, skill atau prompt MCP. Audit receipt native memiliki tipe entitas terpisah dari receipt MCP. Katalog yang sudah ada mencatat `blog.*`, `forms.*`, `media.*`, `meet.*`, dan `links.*`. Harga dan diskusi mempertahankan kontrak UI.
- Admin dapat membuka tautan media, dokumentasi dan Meet di browser sistem atau membagikan tautan Meet melalui panel berbagi perangkat. Aksi memeriksa ulang fokus dan sesi, serta mengirim URL tanpa kredensial transport Expo. Email host yang dikonfirmasi provider hanya dipakai pada pilihan host di `https://meet.google.com`. Tautan pendek dan tautan Google Meet untuk peserta tidak menyertakan pilihan akun host. Tindakan ini khusus UI dan memakai kontrak MCP yang ada.
- Pemilih thumbnail tersedia melalui host `AdminOperationsScreen`. Berkas sementara terikat pada sesi dan draf. Endpoint memeriksa hak Admin aktif, akun, dan ID sesi sebelum membaca multipart, membatasi byte isi permintaan, dan memeriksa kembali peran dan sesi sebelum menyimpan. Jalur web tetap memakai izin tutor atau Admin. Unggahan menyimpan media terpisah dari simpan artikel. Klien tidak mengulang POST secara otomatis.

Tes pertama mencakup inventaris 13 pola, isolasi fixture, penolakan akses, pemulihan baca, revisi draf, konsistensi respons, dan binding transport. Skrip integrasi memakai PGlite dengan migrasi PostgreSQL repo. Cakupannya termasuk sesi dan peran yang dicabut, pengulangan permintaan, benturan payload dan revisi, hak peserta yang gagal sebagian, pending dan hasil provider tak pasti. Tes thumbnail memakai penyimpanan sintetis dan permintaan multipart lokal. Maestro `management.yaml` menjalankan pratinjau draf, validasi editor, detail formulir, pembatalan penghapusan, pemulihan, dan penolakan akses. Bukti perangkat dan diff mengikuti workflow operasi. Paritas piksel belum dinyatakan.

## Referensi web

Fixture `/management` merender halaman Formulir Admin, detail respons, dan komponen Dokumentasi Next.js asli tanpa shell Admin. Playwright memakai data sintetis yang sama dengan Expo, font fixture Zyx, zona UTC, locale `id-ID`, dan sRGB. Server berjalan di port 3211. Capture browser tidak menentukan hasil perangkat.

```sh
NEXT_TELEMETRY_DISABLED=1 node node_modules/next/dist/bin/next dev tests/visual/native-parallel/operations --webpack -p 3211
PARITY_CHROMIUM_EXECUTABLE=/usr/bin/chromium node --import tsx tests/visual/native-parallel/operations/capture-management.ts
```

Enam PNG tersimpan. Lima dibuat pada viewport 380 × 844 DPR 1, termasuk editor formulir, daftar kosong, ringkasan respons, daftar dokumentasi, dan artikel dokumentasi gelap. Capture editor tambahan memakai viewport 402 × 874 DPR 3. Fixture editor mengukur lebar scroll 521 px pada kedua viewport. Daftar berisi belum mencapai data fixture saat batas tunggu. Percobaan berikutnya juga melewati batas tunggu hidrasi dan dihentikan agar capture lain dapat berjalan.
