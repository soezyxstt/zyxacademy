# Academic route inventory

Source snapshot: `native-migration/academic` at `f4ed84dc`. The merge base with the readiness baseline `fa3ce04ed78181810b31ff1b3bf5852c24f6ec5f` is that baseline. The route list is from `plans/native-parallel/routes.tsv`: 36 Admin academic and 18 Tutor routes. Every listed page exists at this snapshot. No runtime, visual, Android, iOS or parity pass is claimed here.

- `route-operations.tsv` has one row per route: page read or redirect, concrete client operations identified, source paths, page gates, known effects, retry gaps, web fixture candidates and the route's exact MCP catalog status. Page inputs beyond path parameters and full handler contracts remain open where the table says so.
- `action-contracts.tsv` deduplicates named web Server Actions across routes and gives their declaration, extracted signature and named guard calls. Extraction is a navigation aid, not proof of the entire guard or effect: inspect each handler and helper before reusing it. The `effect_and_result`, retry, Expo HTTPS and exact MCP mappings remain unverified unless described in the first traces below.
- `http-contracts.tsv` connects selected HTTP calls to the actual handler and marks specifically verified guards and side effects. This list does not yet cover every nested review, discussion, live or indirect request. Those gaps, and all action-level ownership checks and retry identities, prevent an exhaustive backend parity inventory.
- `routes.tsv` retains direct imports, candidate renderers and related MCP catalog entries. Catalog tools are related tools, not a guarantee of action coverage. `no exact source entry` is not proof that no MCP capability exists. Paths are repository-relative. None of these files claim runtime, device, retry, MCP deployment or parity evidence.

## Cross-cutting dependencies and MCP

`app/(admin)/layout.tsx` supplies Admin shell, navigation, command menu, Ops AI and notification initialization. `app/(tutor)/layout.tsx` supplies Tutor shell and navigation and requires the Tutor role with `allowAdmin: false`; `app/(tutor)/tutor/layout.tsx` independently checks with `allowAdmin: true`. These shared shells belong to shared-ui and integration according to the parallel plan, not to this inventory. Detail pages have additional guards that must not be flattened into the layout check. Formula, article, diktat and other complex renderers belong to integration. Candidate paths in the table are discovered by name and import, not a completed dependency audit.

The exact source-level MCP catalog entries for all 36 Admin academic routes are indexed in `routes.tsv`. The catalog explicitly says registration is authoritative and partial coverage does not imply all page actions. The 18 Tutor page paths have no exact catalog source entry at this snapshot. This is not a finding that Tutor-related MCP tools are absent. Each eventual feature change must inspect registered tools, scopes, consent, discovery, playbooks, packaged skills, host prompts, clients and environment bindings, and update affected contracts and focused checks. UI-only operations still need accurate catalog coverage. No MCP contract, published package or deployed server is changed by this inventory.
