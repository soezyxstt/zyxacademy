# Administrasi akademik di Expo

Gunakan `AdministrationProvider` untuk membungkus navigator fixture dan `AdministrationScreen` untuk merender rute yang dikelola. Provider mengikat fixture ke ID akun, peran dan skenario. `useAdministrationSnapshot` memasok perubahan bundle ke daftar review mata kuliah. `administrationCases` di `routes.ts` memuat 57 ID dari 19 pola rute, masing-masing dengan kasus terisi, kosong dan gagal. Rute kompatibilitas mengganti entri navigasi dengan halaman tujuan. Skenario kosong atau error pada alias mengikuti langkah lanjut di tujuan jika alias dapat diselesaikan.

`AdministrationLiveScreen` menerima transport akun aktif. GET pada `/api/native/academic-administration/` memakai sesi yang sama dengan web, memproyeksikan bidang untuk UI native, dan menolak peran selain Admin setelah memeriksa identitas kanonik. Pembacaan meminta ulang data saat gagal, mengikat hasil ke route dan akun aktif, serta mengirim respons `private, no-store`.

Pada `/admin/notifications`, tombol Tulis notifikasi membuka komposer yang terhubung ke `GET/POST /api/native/academic-administration/notifications/broadcast`. Admin memilih audiens, meninjau jumlah penerima serta pesan, lalu mengonfirmasi snapshot. Sesi yang sama dapat memeriksa kembali status setelah respons terputus. Riwayat pengiriman tetap memakai pembacaan administrasi yang ada.

| Alur | Pembacaan produksi | Aksi fixture |
| --- | --- | --- |
| Pengguna, kelompok dan token | `getAdminUsersData`, `getAdminStudyGroups`, `getEnrollmentTokens` | Perubahan peran dan pengelolaan anggota kelompok bertoken |
| Jadwal | `getAdminScheduleData`, termasuk periode, slot, jadwal akademik terbit, tutor, tiket dan audit | Buat atau edit jadwal, ketersediaan, penugasan, relokasi dan pembatalan sesi, sertifikasi tutor |
| Notifikasi | `listAdminNotificationHistory` | Komposisi, audiens, pratinjau, konfirmasi dan pencocokan hasil pengiriman fixture |
| Tutorial PKA | `getPkaRegistrationsAction`, `getPkaAnnouncementsAction`, `getPkaSchedulesAction` | Cari atau lihat status bukti, kelola pengumuman, buat atau edit jadwal PKA |
| Review materi | Daftar detail memakai `resolveCourseIdentity`, `getIdeaBundleImport`, dan `getProductBundleImport`. Detail Idea mendukung pembacaan kutipan dan penyimpanan keputusan item untuk Admin aktif. | Review Product dan keputusan tingkat bundle, revisi konten, terbit, tarik, hapus |
| PDF Diktat | `POST /api/admin/bundles/product/{id}/pdf` mengantrekan pekerjaan, GET hasil permintaan dan GET status khusus memberi status dari server | Antrean fixture dan perubahan status |

Pada `/admin/users`, Expo memakai `getAdminUsersData` untuk pencarian, filter dan paginasi. Admin dapat mengaktifkan atau menangguhkan akun lain setelah konfirmasi nama dan email. Web dan Expo memakai transaksi status yang sama untuk mempertahankan peran legacy saat membuat identitas kanonik dan mencatat invalidasi akses offline. Transaksi memeriksa ulang sesi dan hak Admin setelah mengunci akun pelaku serta akun sasaran. Aksi menangguhkan akun sendiri ditolak. Expo membandingkan revisi status dan mencatat bukti berdasarkan akun, sesi, sasaran dan UUID permintaan. Saat hasil belum diketahui, percobaan ulang memakai UUID dan revisi yang sama. Saat konflik, Admin memuat ulang daftar sebelum mengonfirmasi perubahan baru. Penangguhan memengaruhi akses yang memeriksa status kanonik. Sesi Better Auth akun sasaran tetap tersimpan. Admin dapat mengubah peran dari daftar Expo dengan meninjau akun serta pilihan peran sebelum menyimpan. Web dan Expo menyinkronkan keanggotaan kanonik, peran Better Auth dan invalidasi akses offline dalam satu transaksi. Expo mengikat percobaan ulang ke sesi dan revisi peran. Akun kanonik tanpa keanggotaan terlihat tanpa pilihan awal. `users.set_status` dan `users.set_roles` memakai scope dan persetujuan MCP. Jalankan `node packages/native-parity/academic/local/admin-user-status-smoke.mjs` untuk uji HTTP dan PostgreSQL dengan akun sintetis. [Aksi web](../../../../app/(admin)/admin/(academic)/users/actions.ts), [alat MCP](../../../../lib/admin-mcp/access-tools.ts).

Aksi PDF tersedia pada Diktat dari draf Product V2/V3 yang diotorisasi saat pembacaan. Setelah konfirmasi, Expo membuat UUID dan mengikat percobaan ke revisi serta produk. Percobaan ulang POST menggunakan UUID yang sama dan membutuhkan draf permintaan dalam sesi serta target yang masih ditampilkan server. Tautan pemulihan URL hanya dapat memeriksa status. Bukti yang ditampilkan harus sesuai dengan ID percobaan yang diterima. Rute server menolak origin luar dan mengharuskan tipe konten JSON. Pembacaan status hanya mengembalikan status bukti untuk produk, revisi dan percobaan yang diminta. PDF V4 mengikuti verifikasi tepercaya yang sudah ada.

Di detail Idea per mata kuliah, `GET` dan `PATCH /api/native/academic-administration/bundle/idea/{slug}/{importId}/item/{ideaId}` menggunakan artefak yang divalidasi oleh mekanisme web. Admin dapat membaca pernyataan, penjelasan dan kutipan untuk satu Idea, lalu menyimpan keputusan dan catatan miliknya. Tindakan mengecek revisi artefak dan revisi keputusan Admin yang sama. Pengiriman ulang memakai sesi dan UUID awal. Artefak yang melampaui batas baca native perlu diperiksa di web. Cakupan persetujuan dan publikasi bundle serta alat MCP tetap mengikuti jalur authoring yang sudah ada. [Uji HTTP lokal](../local/README.md).


PATCH pengumuman PKA menyimpan judul dan isi melalui operasi teks yang dipakai web. Transaksi memeriksa sesi aktif, memegang kunci baris, membandingkan revisi teks dan mencatat hasil berdasarkan akun, sesi dan UUID permintaan. Saat konflik, layar menampilkan teks terbaru dan mempertahankan draf untuk percobaan berikutnya. Uji HTTP dan PostgreSQL lokal tersedia melalui `node packages/native-parity/academic/local/pka-announcement-smoke.mjs`, dengan server dan seed dari `../local/README.md`.

Pada `/admin/tutorial-pka/schedules`, Admin dapat mengedit judul, tanggal, jam WIB dan tautan Meet melalui operasi jadwal yang juga dipakai web. API memeriksa sesi, keberadaan jadwal dan revisi di dalam transaksi. Percobaan ulang memakai UUID yang sama. Saat konflik, kolom yang belum diubah mengikuti hasil pembacaan terbaru. Editor menyembunyikan draf saat jadwal dihapus atau akses berakhir. Uji HTTP dan PostgreSQL lokal juga menghapus jadwal melalui editor web sebelum memeriksa percobaan ulang. Lihat [perintah smoke lokal](../local/README.md).

Admin dapat membuat dan menghapus jadwal, mengirim pengumuman PKA, menyematkan pengumuman, serta mengarsipkan atau memulihkannya. Operasi memakai tanda terima yang terikat ke akun, sesi dan UUID. Jadwal mendatang baru dan perubahan tautan Meet sesi mendatang mengantrekan pengiriman melalui worker produk. Jadwal lampau tersimpan tanpa pengiriman. Worker memeriksa sesi Admin, revisi sasaran, dan preferensi peserta serta memakai templat web. Layar membedakan pengiriman antre, berjalan, selesai, sebagian gagal, gagal dan hasil yang belum diketahui. Hasil yang belum diketahui dapat ditinjau melalui daftar. Worker tidak mengirim ulang hasil yang belum terkonfirmasi. Tindakan PKA berada di luar tool, scope, persetujuan, discovery, dan binding MCP. [Kontrak PostgreSQL dengan penyedia sintetis](../../../../tests/contracts/native-pka-lifecycle-integration.test.ts).

Kelompok belajar dapat dibuat dan diedit melalui API native dengan operasi database yang juga dipakai web. Saat membuat kelompok, Admin memilih mata kuliah kanonik aktif. Server mencocokkan relasi legacy yang dipakai tabel kelompok sebelum menyimpan grup dan relasinya dalam satu transaksi. Edit memperbarui profil, paket, kuota, periode, status dan catatan. Mata kuliah kelompok yang sudah ada dapat diubah, termasuk kelompok bertoken. Relasi token tetap mengikuti penawaran yang diterbitkan, seperti pada web. Edit memakai revisi yang mencakup relasi mata kuliah dan penggunaan kuota. Konflik menampilkan pengaturan terbaru dan menggabungkan kembali kolom yang diubah pengguna. Idempotency-Key terikat akun dan sesi agar pengulangan tidak menggandakan grup atau menimpa revisi yang lebih baru. Sebelum mengembalikan hasil edit lama, server memeriksa bahwa kelompok masih tersedia. Jalankan uji HTTP/PostgreSQL dengan `node packages/native-parity/academic/local/study-group-smoke.mjs`.

Admin dapat melihat anggota kelompok biasa dan kelompok bertoken, mencari akun kanonik aktif berdasarkan nama atau email, dan menambah atau mengeluarkan orang setelah konfirmasi. Penambahan berlaku pada kelompok aktif yang belum kedaluwarsa dan memakai operasi web untuk membuat akses kursus yang belum tercatat. Akses kursus yang sudah tercatat mengikuti masa berlakunya saat anggota dikeluarkan. API memeriksa revisi keanggotaan, mata kuliah dan periode setelah mengunci kelompok. Percobaan ulang memakai UUID semula dan bukti terikat ke akun, sesi, kelompok, sasaran dan tindakan. Identitas peserta dan tombol percobaan ulang muncul setelah pembacaan baru mengesahkan sasaran atau menemukan bukti atas permintaan tersebut. Konflik memuat ulang daftar untuk konfirmasi baru. Penetapan ketua tersedia melalui alur yang sudah ada. Alat `groups.members.add` dan `groups.members.remove` tetap memakai scope dan persetujuan MCP dan memakai kunci kelompok yang sama. Jalankan `node packages/native-parity/academic/local/study-group-members-smoke.mjs` untuk uji HTTP dan PostgreSQL dengan akun sintetis.

Detail kelompok memuat token aktivasi dan kapasitas pada `GET /api/native/academic-administration/groups/{groupId}/tokens` setelah Admin memilih kelompok. Endpoint memerlukan sesi Admin aktif, membatasi hasil ke kelompok tersebut dan mengirim `Cache-Control: private, no-store`. Tombol salin memakai papan klip perangkat. Daftar kelompok tetap memuat ringkasan. Alat MCP `groups.inspect` dan `tokens.get` mengembalikan metadata, dan `tokens.reveal` memerlukan scope `access:secrets:read`. Discovery, persetujuan, playbook, skill, prompt host, klien dan lingkungan MCP mengikuti kontrak yang sama. `expo-admin-group-tokens.test.ts` memeriksa penolakan akses, cakupan kelompok, proyeksi dan kebijakan cache. Papan klip perangkat belum diverifikasi.

Admin dapat membuat dan mencabut token pendaftaran. Penerbitan memakai generator web, masa berlaku semester, dan transaksi tunggal untuk token, kelompok, serta relasi mata kuliah. Server memeriksa mata kuliah kanonik aktif dan mengikatnya ke identitas yang dipakai pendaftaran. Pencabutan mengakhiri masa berlaku token untuk pendaftaran baru. Peserta yang terdaftar memakai masa akses masing-masing. Admin dapat menyalin token dari detail. Hapus kelompok atau token membuka ringkasan dampak dan memerlukan konfirmasi atas revisi yang ditampilkan. Menghapus token menghapus kelompok tertaut dan data yang ikut terhapus sesuai aturan relasi web. Akses pendaftaran per mata kuliah mengikuti masa berlaku sendiri. Percobaan ulang memakai permintaan dan sesi yang sama. MCP `tokens.revoke` tetap mengakhiri masa berlaku token. Lookup dan respons mutasi API editor berisi metadata. Kode tersedia pada daftar token untuk Admin yang berwenang. Pengulangan perintah mengikat akun, sesi dan identitas permintaan. Uji lokal `node packages/native-parity/academic/local/enrollment-token-smoke.mjs` memeriksa format sebagai nilai boolean.

Jika pembacaan atau penyimpanan token mengembalikan 401, 403, atau 404, layar menutup detail yang terbuka dan menghapus daftar sampai pembacaan baru berhasil. Gangguan sementara pada penyimpanan mempertahankan ID permintaan untuk percobaan ulang. Uji perilaku ini tersedia di `tests/native-parity/academic/access-recovery.behavior.cjs` dengan dependensi sesuai [kontrak pengujian komponen](../../../../apps/mobile-native/features/shared-ui/CONTRACTS.md#uji-perilaku-kontrol).

Layar memakai Calendar bersama untuk jadwal fixture dan jadwal dari server, ResponsiveTable untuk riwayat notifikasi, serta SharedDialog melalui komposit akademik. Pemetaan produksi mencakup pembacaan, status pengguna, grup belajar biasa dan bertoken beserta anggotanya, penerbitan dan pencabutan token, edit teks pengumuman, serta antrean PDF. Alur terhubung untuk setiap permukaan dirinci di atas dan di bawah bagian ini. Preview file bukti PKA, renderer konten lengkap dan unduhan PDF tetap merupakan dependensi integrasi. PKA tetap di luar katalog MCP. Pembacaan native dan PDF V2/V3 tercatat sebagai aksi UI. Alat authoring, scopes, consent, discovery, playbook, skill, host prompt dan binding lingkungan MCP mengikuti kontrak saat ini. Tidak ada migrasi database atau perubahan deployment.

Jalankan cek domain dan adapter dengan `node_modules/.bin/tsx --test packages/native-parity/academic/administration/administration.test.ts`. Skenario Maestro `administration-conflict.yaml` dan `administration-bundle.yaml` berada di `.maestro/native-parallel/academic/`. Perbandingan piksel Playwright, Android dan iOS serta hasil antrean eksternal memerlukan verifikasi lanjutan.

Pada kalender dan daftar akademik di `/admin/schedules`, Admin dapat membuat, mengedit dan menghapus agenda. Editor memakai zona WIB dan mempertahankan mata kuliah, waktu dan keterangan dari data web. Simpan dan hapus memeriksa revisi agenda dan mengantrekan sinkronisasi kalender pusat melalui jalur yang juga dipakai web.

Review Product Bundle membuka isi produk serta endpoint detail, review item, revisi dan publikasi yang sama dengan web. Pilihan bagian atau blok mengikuti format artikel. Rubrik pedagogik mengirim keputusan, alasan dan bukti yang dipilih reviewer. Publikasi memeriksa keputusan, kesiapan rilis, dependensi dan status PDF. Setelah respons yang tidak pasti, baca kembali keadaan server sebelum mengambil tindakan berikutnya.
