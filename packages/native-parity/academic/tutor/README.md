# Alur tutor native

Entri native `TutorScreen` berada di `apps/mobile-native/features/academic/tutor/index.tsx`. Gunakan URL produk yang sama dengan web. Rute kuis dan pengelolaan tryout dirutekan ke fitur Assessment. Pratinjau menggunakan akun tutor sintetis `academic-tutor` dengan `academic-course-1` yang berisi, `academic-course-2` yang kosong, dan `academic-course-3` di luar penugasan.

## Operasi terhubung

| Rute aplikasi | Sumber web dan cakupan native |
|---|---|
| `/tutor` | Dashboard, sesi mendatang, tiket menunggu, dan mata kuliah dari `getTutorDashboardReadModel`. |
| `/tutor/[courseId]` | Ringkasan analitik mata kuliah melalui pembacaan snapshot dan data cohort yang sama. Native menampilkan jumlah peserta, konsep dengan distribusi penguasaan, dan intervensi. |
| `/tutor/[courseId]/participants` | Daftar, pencarian, filter jenis akses, kelompok, dan detail peserta dari `getTutorCourseParticipants`. |
| `/tutor/[courseId]/grading` | Antrean dan pembacaan jawaban tryout memakai `readAuthorizedTryoutGrading` dan pencatatan paparan soal yang sama. Web dan native menerbitkan nilai akhir serta catatan tutor melalui `gradeTryoutSubmission`. Tutor dapat membuka PDF atau gambar dari jawaban esai tersimpan dengan pengunduhan privat di web dan native. |
| `/tutor/schedule` | Minggu, slot, sesi, tiket, dan kelompok dari `getTutorScheduleReadModel`. Kalender menampilkan agenda per tanggal dan dialog tambah/edit ketersediaan 90 menit. Native memakai aturan slot web. Tutor dapat membatasi slot ke mata kuliah yang diampu dan mengulangnya hingga empat minggu. Hasil menunjukkan jumlah minggu yang berhasil dan yang bertabrakan. Tutor dapat menghapus slot kosong, menyalin ketersediaan dari minggu sebelumnya dan memindah sesi ke slot miliknya. Aturan minggu terkunci mengubah permintaan pindah menjadi tiket. Tutor dapat melihat percakapan tiket, membalas, menyetujui atau menolak usulan. Balasan dan keputusan memakai sesi, pemilik slot, ID pengiriman dan transaksi jadwal yang sama untuk percobaan ulang. |
| `/tutor/discussions`, `/tutor/[courseId]/discussions` | Pilih atau bisukan kanal, buat dan cari pertanyaan, jawab atau balas pesan, lampirkan hingga empat gambar, lihat gambar, beri reaksi, tandai halaman dibaca dan selesaikan diskusi sesuai izin. Edit atau hapus pesan yang diizinkan, laporkan pesan, dan teruskan ke audiens yang sesuai. Pilih peserta yang berhak disebut atau minta bantuan dengan @Zyra. Pengiriman memakai sesi, origin tepercaya dan bukti permintaan yang sama. |
| `/tutor/[courseId]/materials` | Tutor dengan penugasan dapat membaca judul dan ringkasan. Akun dengan peran Tutor dan Admin dapat membuat, mengedit dan menghapus materi warisan jika akses mata kuliah dikembalikan sebagai `admin_override`. Editor web dan native memakai parser, pemeriksaan revisi, dan transaksi materi yang sama. |
| `/tutor/[courseId]/videos` | Playlist dan video dari `getCourseVideosData`. Aksi Putar meminta sumber baru melalui sesi Tutor. Pemutar dalam aplikasi menampilkan video HTTPS, video dari proxy privat, serta YouTube. Tutor pengampu dapat membuat, mengedit, dan menghapus daftar putar atau video, menautkan YouTube, serta mengunggah video hingga 100 MiB atau sampul hingga 5 MiB. Server memeriksa berkas sebelum menautkannya ke katalog. Pengambilan cuplikan sebagai sampul tersedia di Zyx web. |
| `/tutor/[courseId]/live` | Buka ruang tunggu dari kuis terbit atau versi soal Python terbit. Mulai sesi, tampilkan jawaban atau hasil, lanjutkan soal dan akhiri sesi. Sesi aktif pulih saat rute dibuka lagi atau koneksi terputus. |
| `/tutor/docs`, `/tutor/docs/[slug]` | Pencarian dan Panduan Tutor ID dari sumber yang juga dipakai web. Diagram web masih dilayani oleh renderer web. |

Tutor support memakai `/api/native/academic/tutor-support/*` melalui `createTutorSupportClient(transport)`. Sesi menentukan akun, role Tutor wajib, dan semua endpoint mata kuliah memeriksa penugasan aktif pada canonical/legacy ID. Respons memakai `Cache-Control: private, no-store`. Jawaban yang pengirimannya belum terkonfirmasi menyimpan isi dan ID yang sama dalam klien terikat sesi. Membuka kembali rute dalam sesi itu mempertahankan percobaan, sedangkan akun atau sesi baru mendapatkan state baru.

Daftar peserta menampilkan inisial, jenis akses, peran kelompok, tanggal pendaftaran, dan masa berlaku. Tombol cari membuka isian pada header. Pemilih **Semua tipe** menyaring jenis akses. Ketuk peserta untuk membuka detail dan gunakan **Kembali** untuk kembali ke daftar dengan filter yang sama. Native mempertahankan nama mata kuliah yang terlihat pada header agar tutor dapat membedakan daftar ketika mengajar beberapa mata kuliah. Navbar web pada 380 px menampilkan judul generik. Tata letak mengacu pada [perbandingan Android 380 × 852](../../../../tests/visual/native-parallel/academic/device/f75e0496914edd53c4bc24487ca58f6ac47a3769/README.md) dari build terdahulu.

Hosting kuis langsung memakai `GET` dan `POST /api/native/academic/tutor-support/courses/{courseId}/live/host`. Penugasan kursus dan kepemilikan sesi diverifikasi sebelum kredensial realtime atau kontrol tersedia. Pembukaan dan kontrol memakai API Live web serta kontrak Worker yang sama. Native membaca fase dari WebSocket dan meminta kredensial baru saat menyambung kembali. Jika hasil kontrol belum terkonfirmasi, tutor membaca status terbaru sebelum mengirim lagi. Sesi coding ad hoc memakai versi soal Python terbit milik mata kuliah yang dipilih. Web dan native memakai kebijakan yang sama, yaitu lima menit, petunjuk, tanpa batas percobaan, dan skor terbaik.

Dokumen warisan di `/tutor/{courseId}/materials` memakai `GET` dan `POST /api/native/academic/tutor-support/courses/{courseId}/materials/legacy` untuk editor Admin. Akses hanya-baca tetap mengikuti penugasan Tutor. Penyimpanan mengganti bagian dan chunk dalam satu transaksi. Pengubahan dan penghapusan memeriksa revisi yang dibaca; percobaan ulang memakai bukti yang terikat sesi, akun, mata kuliah dan perintah.

MCP tidak menambah tool, scope, persetujuan atau kredensial hosting. Operasi dicatat sebagai UI-only di katalog dan dibuktikan oleh kontrak klien/otorisasi, kontrak Live web dan alur Android dengan Worker loopback.

Penerbitan nilai memakai `POST /api/native/academic/tutor-support/courses/{courseId}/grading/{submissionId}` dengan nilai bulat 0 sampai 100, catatan maksimal 4.000 karakter, revisi yang dibaca dari antrean, dan header `Idempotency-Key`. Server mengunci pengumpulan dan memeriksa sesi, peran, penugasan, tipe ujian, isi jawaban, serta revisi. Nilai dan bukti penerimaan berada dalam satu transaksi PostgreSQL. ID penerimaan bergantung pada akun, sesi, mata kuliah kanonis, pengumpulan dan ID permintaan. Klien mempertahankan draf atau permintaan yang belum terkonfirmasi selama sesi aplikasi yang sama. Setelah konfirmasi, klien memuat ulang antrean. Konflik membuka tindakan untuk membaca nilai terbaru.

Lampiran esai native memakai `GET /api/native/academic/tutor-support/courses/{courseId}/grading/{submissionId}/attachment/{questionId}`. Server memeriksa sesi Tutor saat ini, penugasan, status pengumpulan tryout dan referensi berkas pada jawaban yang dipilih. Proxy penyimpanan yang sama dengan web memeriksa akun pengunggah dan versi objek sebelum mengirim PDF atau gambar hingga 10 MiB. Native membuka salinan sementara melalui pemilih aplikasi perangkat. Operasi ini tidak menambah akses MCP.

`POST /api/native/academic/tutor-support/schedule/slots` membuat ketersediaan tutor, dan `PATCH /api/native/academic/tutor-support/schedule/slots/{slotId}` menyunting slot milik tutor yang sama. Edit mengirim revisi dari GET jadwal. Server memakai kunci jadwal serta aksi tambah/edit web, sehingga durasi, benturan waktu, tanggal, mode dan lokasi diperiksa di transaksi yang menyimpan slot, catatan, dan bukti penerimaan. Riwayat pemesanan melindungi slot dari pengeditan. Native mempertahankan isi dan ID permintaan saat hasil belum terkonfirmasi dan membaca agenda lagi setelah tersimpan.

Jika API jadwal atau slot mengembalikan 401, 403, atau 404, layar menutup dialog dan mengosongkan jadwal hingga GET yang baru berhasil. Gangguan sementara saat memuat ulang mempertahankan jadwal terakhir yang sah.

## Verifikasi

- `bun test packages/native-parity/academic/tutor` menguji akses, snapshot lama dan baru, status kosong, retry, serta batas kontrak API. Uji command menyimulasikan respons hilang lalu memeriksa ID yang tetap sama dan pembacaan ID pesan.
- `node --test tests/native-parity/academic/access-recovery.behavior.cjs` menguji penghapusan agenda dan draf dari layar serta pemulihan lewat GET baru. Siapkan `ZYX_CONTROL_TEST_DEPS` sesuai [kontrak pengujian komponen](../../../../apps/mobile-native/features/shared-ui/CONTRACTS.md#uji-perilaku-kontrol).
- `tests/contracts/tutor-grading-scope.test.ts` memakai PostgreSQL sintetis untuk membuktikan isolasi sesi, pemutaran ulang ID, penolakan lintas kelas dan tipe ujian, konflik setelah perubahan jawaban atau penilaian web, serta rollback ketika pencatatan bukti penerimaan gagal.
- `tests/contracts/native-tutor-slot.test.ts` menguji tambah/edit, kepemilikan dan izin sesi, revisi, benturan, slot dengan riwayat pemesanan sintetis, serta rollback atomik slot dan catatan jika bukti penerimaan gagal ditulis.
- `maestro test .maestro/native-parallel/academic/tutor-assigned.yaml` membuka dashboard, mata kuliah, peserta dan penilaian tryout, termasuk detail dan Back. Flow `tutor-empty-denied.yaml` dan `tutor-retry.yaml` mencakup penugasan yang kosong, penolakan dan pemulihan. Flow `tutor-schedule.yaml` memilih tanggal, membuat slot, membuka dialog edit, lalu kembali ke slot setelah pindah minggu. Jalankan pada build aplikasi dengan skema `zyx-native-parity`.
- Bukti emulator, simulator dan perbandingan piksel masih memerlukan run perangkat. Pratinjau sintetis menjalankan penilaian, jadwal, jawaban diskusi, dan fase kuis langsung dari data milik sesi pratinjau.

## MCP

HTTP native menggunakan sesi aplikasi dan layanan web. Jawaban dan balasan kontekstual memakai aksi `reply` dan mencocokkan `requestId` dengan `Idempotency-Key`. Aplikasi membaca kembali pesan berdasarkan ID yang dikembalikan. Lampiran memakai endpoint diskusi dengan otorisasi channel dan penyimpanan privat. Reaksi, penandaan baca dengan bukti observasi dan konfirmasi status memakai layanan diskusi yang sama. Sebutan memakai pencarian nama yang sama dengan web dan hanya mengembalikan anggota yang dapat disebut di thread tersebut. Identitas ambigu tidak dapat dipilih. Aplikasi mengirim ID dan handle yang cocok dengan isi pesan, maksimal sepuluh, lalu server memeriksa akses anggota kembali. Tombol Tanya Zyra memasukkan @Zyra ke draf. Antrian Zyra menggunakan konteks, kuota dan aturan penilaian web, serta menampilkan status pada pesan pemanggil. Sesi yang sama mempertahankan balasan, lampiran dan pilihan peserta ketika thread dibuka kembali. Percobaan tanpa konfirmasi mempertahankan seluruh payload dan ID sebelumnya.

Menu tindakan memakai izin pesan web dan memeriksa kembali thread serta target sebelum menulis. Edit memakai revisi pesan. Terusan memakai satu ID percobaan dan memeriksa dua audiens. Kanal privat tidak dapat menjadi sumber atau tujuan terusan. Tutor dapat melaporkan pesan sesuai izin; resolusi laporan mengikuti permukaan Admin.

Tool, scope, consent, capability discovery, playbook, paket skill, prompt host, dan binding eksternal mengikuti kontrak MCP yang sudah ada.
