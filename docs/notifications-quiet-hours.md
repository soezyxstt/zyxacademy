# Quiet hours and signed-in sessions

- Preferences apply to account-wide **push notifications**, not transactional email. The inbox retains individual updates immediately. Default is off; start and end are local wall-clock times in the chosen IANA zone.
- During a quiet window, ordinary and discussion pushes enqueue the persisted notification ID in a durable Postgres queue. A Cloud Tasks job runs at the end; hourly recovery covers an enqueue outage. The worker rechecks the current preference, current unread state and discussion visibility, then sends one privacy-safe digest per bounded page. Stable OS notification tags replace repeat digest banners. Provider delivery remains at-least-once.
- Desktop's authenticated inbox polling stops advancing its cursor during quiet hours. Native app delivery depends on Android notification permission and correctly configured FCM. OS-level DND can still suppress banners.
- Session listing returns only IDs, device labels and timestamps. The session token and raw IP are never exposed. Remote sign-out uses Better Auth's revocation endpoint; session-bound push tokens cascade on deletion. Legacy unbound tokens rebind at the next registration. Session renewal time is not a precise last-activity timestamp.
- Never infer that two Chrome/Capacitor registrations belong to one physical device by IP or user agent. Only retire the browser push token automatically if a native registration proves that it shares the same authenticated session. Existing independent Chrome subscriptions can still be opted out explicitly.
- Android has a browser cleanup action in notification preferences. It opens the original browser and requires a separate explicit click to unsubscribe only that browser. A local pause flag prevents immediate re-registration; the browser can explicitly re-enable later.
- Native local study reminders shift their recurring wall-clock schedule to the next non-quiet minute using the latest synced account preference. One-off session reminders move to the quiet end only if that is still before the session starts. Offline devices cannot instantly learn about remote changes or revocations; recurring schedule changes across differing DST zones require a foreground sync.
- Android uses notification categories and conversation tags (replacement/grouping by thread, not full Android MessagingStyle). Active, visible discussion toasts and web foreground banners are suppressed.
- Device validation: install Nightly, allow OS notifications, test foreground/background/terminated (not force-stopped), log into Chrome separately, verify no cross-device token is removed, test overnight and non-overnight quiet windows and changes while queued, revoke an independent browser/device session, verify it cannot access protected routes and stops receiving push.
- Rollout: apply the additive migration before web/worker deployment and build a new Nightly for Android channel changes.
