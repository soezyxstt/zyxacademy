# Roadmap mobile native Expo dan Next.js

Status: **prototipe lokal dan rencana, belum menjadi kontrak runtime atau rilis**. Next.js tetap melayani web dan backend; aplikasi Expo React Native yang diusulkan adalah klien tambahan dalam repositori yang sama. Migrasi dilakukan bertahap dan Capacitor tetap menjadi jalur mobile sampai setiap alur penggantinya lolos verifikasi dan keputusan rilis dibuat. Status deployment dan perilaku aktif tetap mengikuti [arsitektur](ARCHITECTURE.md), [fitur](features.md), dan [prosedur rilis](DEPLOYMENT.md).

Ketukan push FCM dan APNs memakai ID notifikasi yang tersimpan di server. Expo memanggil `/api/notifications/history?tapId=…` dengan sesi aktif dan memeriksa rute serta peran sebelum membuka tujuan. Ketukan menunggu verifikasi untuk sesi yang sama. Jika pencarian mendapat 401, Expo memeriksa ulang sesi sebelum mencoba pencarian sekali lagi. Setelah rute terbuka, aplikasi mengirim tanda baca sekali melalui `/api/notifications/read`. Ringkasan jam tenang hanya membuka beranda jika peran dan sesi sudah terverifikasi saat ketukan diterima. Bukti perangkat untuk pengiriman FCM dan APNs masih diperlukan.

Pencarian di navbar Murid, Tutor, dan Admin membaca hasil dari `GET /api/search` menggunakan sesi yang sedang aktif. Pemilihan hasil memeriksa peran dan ketersediaan rute di aplikasi. Tautan marketing, blog, formulir, dan Meet membuka situs. [Pencarian Expo](../apps/mobile-native/features/site-search/search.tsx).

## Sesi build internal

Pada branch integrasi, `zyx-native-parity://internal/session` membuka pemeriksaan akun untuk build native. Sesi memakai login Google di browser sistem pada origin staging. Aplikasi menyimpan verifier acak di SecureStore sebelum membuka browser. Server mengikat kode pada tantangan S256 dan mengirimkannya di fragmen callback. Endpoint `POST /api/auth/native/expo/exchange` memerlukan verifier untuk menukar kode sekali dengan cookie sesi Better Auth. Server memeriksa ketersediaan akun saat pertukaran. Login ini berbagi sesi database dengan login browser yang memulainya.

Produk native dapat menggunakan `useNativeSession()` dari `apps/mobile-native/auth/session-provider.tsx` untuk memperoleh transport yang telah memeriksa identitas pengguna. Pengujian runtime membutuhkan server dengan perubahan yang sama, build Android/iOS yang mengenali skema internal, serta Google OAuth untuk origin staging. Halaman pemeriksaan akun adalah alat integrasi. Bukti paritas visual untuk halaman login produk dilacak terpisah.

Pengaturan Murid menyimpan tema dan preferensi getar di perangkat. Pilihan tetap berlaku saat akun berganti. Kontrol pilihan dan tombol navigasi atas memakai preferensi yang sama. [Preferensi perangkat](../apps/mobile-native/device/preferences-provider.tsx), [umpan balik sentuh](../apps/mobile-native/device/haptics.ts).

Shell produk, handoff browser dan kanal push memakai bahasa akun terverifikasi, bahasa sesi offline yang tersimpan, atau bahasa perangkat. Shell Murid, Tutor dan Admin menampilkan lonceng untuk riwayat notifikasi penerima saat sesi dan perannya terverifikasi. Pengguna dapat membuka tujuan yang diizinkan atau menandai notifikasi sebagai dibaca. Pengujian transport dua akun mencakup pembacaan dan perubahan status melalui handler Next.js serta PostgreSQL uji. [Kotak masuk Expo](../apps/mobile-native/features/notification-inbox/bell.tsx), [pengujian backend](https://github.com/soezyxstt/zyxacademy/actions/runs/45846036130/job/140001017502), [kontrak notifikasi](notifications.md).

Pada build yang mendukung push, Tutor dan Admin dapat memilih **Aktifkan notifikasi perangkat** dari kotak masuk yang terbuka. Sistem baru meminta izin setelah tombol dipilih. Jika sistem tidak bisa meminta izin lagi atau izin sudah diberikan, pengguna dapat membuka pengaturan aplikasi di perangkat. Murid mengelola izin melalui Pengaturan. Aksi perangkat ini menggunakan sesi yang sama dan tidak menambah operasi MCP. [Aksi notifikasi perangkat](../apps/mobile-native/features/notification-inbox/staff-device-push.tsx).

Menu akun Expo memakai konteks sesi aktif untuk menampilkan profil Murid, preferensi, dan tautan dasbor yang sesuai dengan peran yang terverifikasi. Akun khusus Tutor atau Admin dapat mengubah tema dan getaran perangkat dari menu yang sama. Semua peran memakai alur keluar Expo yang mencabut sesi dan mengosongkan state lokal. Menu ini memakai kontrak autentikasi yang sama, tanpa perubahan tool, scope, consent, atau binding MCP. [Menu akun Expo](../apps/mobile-native/routing/account-menu.tsx).

Navigasi kursus biasa di Expo memakai tab dan tujuan pindah kelas dari model Student web. Pemilih menampilkan kelas yang diikuti dalam sesi aktif, kelas yang sedang dibuka, dan tautan ke katalog. Pindah kelas mempertahankan bagian yang tersedia dan membuka daftar pada kelas tujuan. Materi terkunci tetap menampilkan navigasi kursus, sedangkan pembaca memakai kontrolnya sendiri. Endpoint navigasi hanya mengirim metadata. Layar dan API tujuan tetap memeriksa akses, dengan cakupan dan persetujuan MCP yang sudah terdaftar. [Kontrak navigasi](../tests/contracts/student-navigation-query.test.ts), [fixture perangkat](../.maestro/native-parallel/student/course-navigation.yaml), [katalog operasi](../lib/admin-mcp/operations-catalog.ts).

Admin Expo dapat membuat mata kuliah dari daftar dan mengarsipkannya dari Pengaturan setelah konfirmasi. Pengarsipan memeriksa revisi dan referensi materi atau aktivitas, lalu mencabut akses offline melalui alur server yang sama. Coba lagi memeriksa hasil operasi yang sama dalam sesi aktif. Build produk Expo mengutamakan tujuan dari tautan langsung atau login. Pemeriksaan akses data tetap dilakukan oleh layar dan API masing-masing. Rute publik, auth, MCP, API, pengelolaan kredensial, fragmen, dan parameter di luar daftar yang didukung tidak disimpan. Keluar atau pencabutan akses akun membersihkan riwayat sesi. Dashboard peran dipakai ketika riwayat tidak bisa dibuka. [Riwayat rute Expo](../apps/mobile-native/routing/route-history.ts).

## Metadata dan paket bacaan offline

Provider Expo menyinkronkan metadata saat ada layar yang meminta kursus. Respons sync dan manifest harus cocok dengan akun, sesi, origin, bahasa dan hak akses saat ini. SQLite menyimpan metadata per akun, origin dan bahasa. Setiap rekonsiliasi menyelesaikan manifest lebih dahulu, kemudian mengakui cursor. Revisi penyimpanan mencegah respons lama menghidupkan kembali entri yang dicabut. [Kontrak sync](operations/offline-data-sync.md), [provider Expo](../apps/mobile-native/offline/lifecycle-provider.tsx).

Saat aplikasi aktif kembali atau koneksi pulih, Expo memeriksa sesi dan peran Murid sebelum melanjutkan sinkronisasi. Koneksi yang belum diketahui tidak dianggap pulih. Sinkronisasi metadata berhenti ketika aplikasi masuk latar belakang, koneksi terputus, sesi kedaluwarsa, atau verifikasi dimulai. Expo tidak menjadwalkan sinkronisasi saat aplikasi berada di latar belakang.

Unduhan manual Expo menyimpan data bacaan mentah Artikel dan Diktat dari `/api/offline/resource`. Paket baru tersimpan setelah semua gambar wajib selesai diambil dari `/api/offline/asset` dengan identitas, revisi, ukuran dan SHA-256 yang cocok. Jenis yang diterima meliputi PNG, JPEG, WebP, GIF dan AVIF. Satu gambar dibatasi 8 MiB dan satu paket 25 MiB. SVG wajib, gambar yang tidak didukung atau paket yang gagal dilengkapi tidak berstatus terunduh. Video, PDF Diktat, dokumen interaktif jarak jauh dan tindakan server memerlukan koneksi. Rendering bacaan native memiliki tahap implementasi tersendiri.

Unduhan manual mengikuti batas kebijakan server, hingga 250 paket dan 100 MiB per kombinasi origin, akun, sesi, dan bahasa, serta 200 MiB per sandbox aplikasi. Pembacaan juga memerlukan kecocokan bab, revisi manifest dan masa akses. Keluar atau kehilangan akses Murid yang terkonfirmasi membersihkan paket dan metadata kedua bahasa. Jalur Expo memakai kontrak HTTP yang sama sehingga cakupan, persetujuan, discovery, dan paket MCP mengikuti kontrak sinkronisasi yang ada. Bukti lokal mencakup pengujian Bun dan SQLite dengan respons HTTP terkontrol. Unduhan dan pembacaan melalui build Android atau iOS masih memerlukan verifikasi perangkat. [Kontrol paket Expo](../apps/mobile-native/offline/reading-client.ts).

Manifest terbaru dapat memperbarui verifikasi paket yang masih berlaku. Lease gambar wajib tetap mengikuti respons aset. Paket yang kedaluwarsa, melewati ambang usia konten, terkena invalidasi, atau berasal dari sebelum reset cursor perlu diperiksa lewat resource dan gambar wajib. Setelah sinkronisasi metadata, **Periksa pembaruan** mencoba hingga tiga paket tersimpan dengan batas 25 detik untuk fase ini. Pemeriksaan berikutnya melanjutkan antrean paket yang masih perlu diperbarui. **Hapus unduhan yang tidak tersedia** menghapus paket yang tidak dapat dipakai dalam cakupan pustaka saat ini setelah konfirmasi. Penyimpanan juga membersihkan paket yang melewati masa retensi meski unduhan baru masih melampaui kuota. [Penyimpanan paket Expo](../apps/mobile-native/offline/reading-store.ts).

Migrasi menghapus tabel paket v1 secara atomik dan menyimpan unduhan baru dalam tabel v2. Setelah kembali ke build lama, daftar unduhan lokal mulai kosong dan paket v2 tetap terisolasi dari pembaca v1. Pengujian Bun memeriksa rollback transaksi, batas kuota dan pembaruan, serta perlindungan paket baru dari respons 409 lama. Fixture Maestro mencakup konfirmasi hapus dan hasil pembaruan pada tampilan pustaka. [Fixture pustaka Expo](../.maestro/native-parallel/offline-library.yaml), [katalog operasi MCP](../lib/admin-mcp/operations-catalog.ts).

Jalankan GitHub Actions **Native integration preview** dengan `offline=only` untuk menguji satu sesi Murid sintetis. Jalur ini memeriksa unduhan terlindungi dan pencabutan hak melalui endpoint asli, lalu menggunakan APK Android untuk memeriksa pustaka saat aplikasi dibuka ulang tanpa jaringan sebelum dan sesudah pencabutan. Pilih `offline=also` untuk menggunakan kembali APK pada job Murid. Mode pengujian ini berjalan di runner terisolasi dan memakai layanan loopback, sehingga kontrak dan binding MCP tetap sama. [Flow Maestro offline](../.maestro/native-integration/authenticated/offline), [workflow](../.github/workflows/native-integration-preview.yml).

## Kondisi yang ada

- `apps/mobile` adalah Capacitor 7 alpha yang memuat origin Next.js jarak jauh dalam WebView. Konfigurasi memisahkan aplikasi dan origin nightly/staging dan stable/production. `www/index.html` menguji koneksi lalu membuka aplikasi online. Saat offline, Android menampilkan pustaka dan reader lokal. iOS menyediakan tampilan coba lagi. Paket bacaan mengikat akun, origin, bahasa, masa akses, dan hak bab. Klien Expo perlu menggunakan [kontrak sinkronisasi yang sudah ada](operations/offline-data-sync.md).
- Bridge dan kode `lib/native/` mencakup notifikasi push dan pengingat lokal, kamera dan pemulihan hasil kamera, share dan berkas, haptik, status jaringan dan lifecycle, refresh, deep link, serta pembaruan. Android memiliki plugin `ZyxGoogleAuth`, `ZyxOfflineStore`, dan `ZyxAppUpdater`. Reader offline menyimpan bacaan berdasarkan akun dan dibersihkan saat keluar atau berganti akun. Kehadiran kode dan dependensi bukan bukti konfigurasi atau keberhasilan perangkat di lingkungan yang berjalan.
- Android App Links memerlukan fingerprint penandatangan yang cocok; Universal Links iOS memerlukan Apple team ID. Login Android menggunakan Credential Manager saat tersedia dengan fallback browser; iOS menggunakan browser. Akun tersimpan, izin, dan cache perlu dipertahankan perilakunya. Rincian serta batas verifikasi ada di [README mobile](../apps/mobile/README.md).
- UI web memakai DOM, CSS, Radix dan komponen Next.js. Komponen tersebut tidak otomatis menjadi komponen React Native. Logika domain murni, skema dan token dapat dibagi setelah memisahkan dependensi server dan browser; rendering dan interaksi native perlu implementasi sendiri.
- `apps/mobile-native` memuat galeri komponen, rute sesi, pustaka offline, handoff browser dan integrasi perangkat. CI gabungan juga memasang entry dari empat branch eksternal di checkout sementara. Komponen dan halaman mendapat kredit setelah hasil visual serta interaksinya diverifikasi pada Android dan iOS. [Petunjuk build internal](../apps/mobile-native/README.md), [audit dan bukti CI](native-readiness.md).
- Root memakai Bun dan saat ini tidak mendeklarasikan workspace; scaffold memiliki lockfile npm sendiri. Penambahan workspace bersama merupakan keputusan lanjutan. [Expo mendukung monorepo Bun](https://docs.expo.dev/guides/monorepos/), tetapi versi dan resolusi modul native harus diuji bersama.

Lihat [audit kesiapan Expo](native-readiness.md) untuk cakupan komponen, halaman dan fungsi backend serta bukti per platform.

## Urutan dan gerbang paritas

1. Bangun inventaris komponen web dan token dari `app/globals.css` dan `components/ui/`. Buat padanan native terisolasi dan galeri untuk pemeriksaan. **Setiap komponen memiliki tiga kasus yang diperiksa satu per satu** terhadap referensi web dengan viewport, skala, font, tema dan state yang ditentukan. Kasus awal separator adalah horizontal light, vertikal light, dan horizontal dark. Catat ukuran, warna, posisi dan hasil perbandingan piksel untuk tiap kasus; perbedaan font rasterization, density dan platform perlu dicatat, bukan diam-diam dianggap identik. Lanjut hanya setelah ketiganya memenuhi paritas piksel yang diminta dan interaksinya terverifikasi bila ada.
2. Susun layout dari komponen yang lolos, lalu komposit: dialog, grid, tabel, kalender, list, navbar, dan bottom navigation. Terapkan tiga kasus serta pemeriksaan fokus, pembaca layar, sentuhan, ukuran teks, safe area, Back, state kosong dan konten panjang sesuai relevansi. Jangan menandai komposit selesai hanya karena komponen penyusunnya lolos.
3. Susun halaman dari komposit yang lolos dan verifikasi alur serta state terhadap web. Setelah itu kerjakan renderer artikel dan diktat, termasuk formula, gambar, tabel, visual dan konten interaktif, hak akses, bacaan tersimpan dan pemulihan offline. Komponen, layout, komposit, halaman dan renderer memiliki bukti serta gerbang masing-masing; belum ada klaim paritas penuh atau rilis hanya karena scaffold tersedia.

Untuk setiap tahap simpan sumber referensi, versi/commit, perangkat atau emulator, dimensi dalam piksel dan density, tema, tiga kasus, screenshot, hasil perbandingan, selisih yang diketahui, dan keputusan lulus/gagal. Jalankan juga pada Android dan iOS nyata sebelum rilis. Paritas gambar tidak menggantikan pengujian perilaku, aksesibilitas, keamanan, atau data.

## Batas data, identitas dan MCP

- SSR dan hidrasi tetap berjalan pada alur web Next.js. Layar React Native merender data terstruktur dari API HTTPS. Expo mengakses operasi yang sah melalui API HTTPS Next.js dengan kontrak tervalidasi dan otorisasi server per permintaan. Server Actions, RSC, cookie browser dan akses langsung database tidak diasumsikan bekerja sebagai API native. Tambah Route Handler khusus hanya jika diperlukan, dengan validasi, batas respons dan uji kontrak. [Route Handler adalah endpoint publik](https://nextjs.org/docs/app/guides/backend-for-frontend), sehingga tetap perlu autentikasi dan otorisasi.
- Pertahankan Better Auth, RBAC, akun tersimpan dan isolasi sesi. Evaluasi integrasi resmi [Better Auth untuk Expo](https://better-auth.com/docs/integrations/expo), penyimpanan sesi di SecureStore, browser sistem, PKCE dan callback yang dibatasi per lingkungan. Verifikasi login, batal, expiry, logout, pergantian akun dan deep link pada perangkat, termasuk kompatibilitas sesi Capacitor yang sudah terpasang. Expo Go tidak cukup untuk menguji redirect OAuth dengan scheme aplikasi; gunakan [development build](https://docs.expo.dev/guides/authentication/). Jangan menyimpan secret provider dalam aplikasi.
- Gunakan kontrak POST dan stream Zyra di `app/api/zyra/chat/route.ts` serta pembaca UTF-8 bersama `packages/zyra/stream.ts` dan adapter web `lib/zyra/stream-consumer.ts` sebagai acuan, termasuk `requestId`, pembatalan, `text-replace`, error dan `[DONE]`. Evaluasi Expo Fetch untuk pembacaan inkremental terautentikasi dan uji pada perangkat Android dan iOS sebelum mengandalkannya.
- Ikuti `lib/offline/sync-contract.ts`, `lib/offline/sync-client.ts` dan `docs/operations/offline-data-sync.md` untuk identitas akun, origin dan bahasa, lease akses, cursor, manifest serta penggantian paket lengkap. Stream hanya memberi petunjuk; sinkronisasi memulihkan perubahan yang terlewat. Verifikasi penghapusan akses dan isolasi saat logout atau ganti akun.
- Pertahankan PostgreSQL sebagai sumber kebenaran server, bucket privat dan URL terotorisasi; penyimpanan lokal hanyalah cache atau data offline yang dibatasi akun, bukan replika database otoritatif. Rancang kedaluwarsa, penghapusan saat logout/switch, batas ukuran, migrasi, konflik dan hak akses ulang. Jangan mengantre mutasi offline tanpa kontrak idempotensi dan pemulihan yang eksplisit.
- Migrasi tampilan saja tidak menambah tool MCP. Per perubahan alur, periksa [katalog operasi](operations/admin-mcp.md), tool, scope, consent, discovery, playbook, skill terkemas, host prompt, klien dan binding lingkungan; perbarui kontrak serta pemeriksaan terkait bila kapabilitas atau semantik berubah. Pertahankan operasi yang khusus UI dalam katalog cakupan. Perubahan lokal tidak berarti paket MCP dipublikasikan atau server dideploy.

### Dokumen dan berbagi berkas

Rute internal `/internal/files` menyediakan pemilihan PDF, berbagi tautan, dan unduhan diktat berdasarkan ID. Adapter memeriksa sesi, draft, jenis dan batas ukuran yang ditetapkan pemanggil. Unduhan pribadi tetap melalui endpoint HTTPS yang memeriksa hak akses diktat dan lampiran diskusi. Tidak ada perubahan pada tool, scope OAuth, consent, discovery, playbook, skill terkemas, host prompt, atau binding staging.

Android membuka URI dokumen dari pemilih sistem dan menyalin data secara bertahap sesuai batas ukuran. Modul lokal memakai stream berurutan dari ContentResolver untuk dokumen cloud yang mengirim pipe atau tidak melaporkan ukuran. Batas byte diperiksa saat membaca. Pada iOS, DocumentPicker SDK 58 memakai impor sementara UIKit dan belum menyediakan opsi membuka dokumen di tempat. UIKit dapat menyalin dokumen sebelum aplikasi memeriksa ukuran. Aplikasi melewati salinan tambahan Expo, membatasi salinan miliknya, dan menghapus impor yang dikenali di folder sementara sandbox saat pemilih mengembalikan hasil. UIKit mengelola masa simpan impor sementara saat proses berakhir. [Dokumentasi Expo DocumentPicker](https://docs.expo.dev/versions/v58.0.0/sdk/document-picker/), [kontrak impor UIKit](https://developer.apple.com/documentation/uikit/uidocumentpickerdelegate/documentpicker%28_%3Adidpickdocumentsat%3A%29?changes=_9&language=objc).

Ekspor Android menyimpan salinan terpisah hingga dua menit setelah panel berbagi ditutup agar aplikasi tujuan sempat membacanya. File dihapus saat sesi berakhir, saat timer berjalan, atau pada pemeriksaan pertama saat aplikasi kembali aktif. Saat aplikasi dibuka ulang, hanya direktori sementara yang dimiliki adapter yang dibersihkan. Jika proses ditangguhkan, penghapusan berbasis JavaScript menunggu proses berjalan kembali. Salinan atau deskriptor berkas yang sudah diterima aplikasi tujuan mengikuti kendali aplikasi tersebut. Panel berbagi yang ditutup tidak mengonfirmasi pengiriman. Uji akses terlambat dan pembersihan ini di perangkat Android dan iOS.

## Performa, perangkat dan rilis

- Ukur cold/warm start, waktu interaktif, frame drop saat scroll, memori, ukuran unduhan dan jumlah request pada perangkat kelas rendah serta koneksi lambat sebelum memilih target dan optimasi. Gunakan navigasi native, pemuatan bertahap, daftar tervirtualisasi, thumbnail dan pagination. [FlatList](https://reactnative.dev/docs/optimizing-flatlist-configuration) memiliki kompromi memori, respons dan area kosong yang perlu diukur pada data sebenarnya.
- Pertahankan kunci TanStack Query yang terikat akun, kebijakan freshness dan invalidasi sesuai [kontrak fetching](data-fetching.md). Pertimbangkan `expo-image` untuk cache memori/disk dan prefetch terbatas, tetapi tentukan perlakuan gambar privat, URL kedaluwarsa, kuota dan pembersihan lintas akun sebelum mengaktifkan cache persisten. SecureStore untuk kredensial kecil, bukan konten besar. SQLite atau filesystem dapat dievaluasi untuk bacaan offline dengan kontrol privasi dan migrasi; tidak menggantikan PostgreSQL server.
- Untuk suara materi, evaluasi pemutaran, interupsi audio dan pilihan keluaran dengan [Expo Audio](https://docs.expo.dev/versions/latest/sdk/audio/). Minta izin mikrofon saat pengguna memilih merekam.
- Petakan dan uji fitur satu per satu: push FCM/APNs, izin dan token perangkat, pengingat lokal, kamera dan pemulihan, share/file, haptik, konektivitas, refresh, link, safe area, browser login, pembaruan serta offline. Pilih modul Expo atau modul native kustom sesuai kebutuhan, dan rencanakan migrasi token serta kompatibilitas perangkat lama. Ketersediaan modul bukan bukti paritas.
- Pisahkan konfigurasi, identifier, signing, origin, kredensial push dan callback nightly/staging dari stable/production. Pertahankan rollback ke Capacitor dan rencana migrasi instalasi, deep link dan sesi sebelum mengganti aplikasi rilis. Uji pembaruan dan instalasi nyata di kedua platform, termasuk jalur store untuk binary baru.

Dokumen ini hanya mencatat rencana dan inventaris lokal. Build, pengujian perangkat, perubahan layanan, penerbitan paket, staging dan production belum dibuktikan oleh dokumen ini.
